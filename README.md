# energo_bot

Telegram bot which forecasting status of light at the home

## Режими роботи

Зараз працює лише стандартний режим: усі користувачі потрапляють у нього одразу, вибору режиму
й кнопки «Змінити режим» немає. Розширений режим (IP) вимкнено, але код збережено: щоб увімкнути
його знову, додайте в `.env` рядок `EXTENDED_MODE=1`, тоді з'являться вибір режиму й кнопка
«Змінити режим» (команда `/restart` теж працює лише тоді). Колишні користувачі розширеного режиму
під час вимкнення автоматично переходять у стандартний, їхні IP-адреси в БД не чіпаються.

- **🏠 Стандартний** — моніторинг світла за адресою (за замовчуванням Богдана Хмельницького 67а).
  Бот раз на 2 хвилини питає Tuya Cloud, чи пристрій онлайн (`TUYA_POLL_SECONDS`). Побачивши
  зміну, він через 15 секунд перепитує стан і пише всім користувачам цього режиму
  «🔴 Світло зникло о 14:05» / «🟢 Світло з'явилось о 17:30, не було 3 год 25 хв», лише якщо
  перевірка підтвердила (короткий збій Wi-Fi не дає хибної тривоги). Тож сповіщення
  приходить через інтервал опитування + ~15 с (плюс власна затримка Tuya 1–3 хв).
  Поточний стан бачить кожен у панелі (`/start`, `/menu` або будь-яке повідомлення): вона
  показує результат останнього опитування і не витрачає запитів до Tuya. Сповіщення про
  зникнення і появу світла можна вимкнути й увімкнути кнопкою «🔕 Вимкнути / 🔔 Увімкнути
  сповіщення» (за замовчуванням увімкнені). Нічого додавати не потрібно.
  Push-канал Tuya (`TUYA_PUSH=1`) вимкнено: для цього проєкту Tuya подій у нього не шле.
- **🛠 Розширений** (за `EXTENDED_MODE=1`) — моніторинг IP-адрес: бот пінгує їх кожні N хвилин
  (`IP_CHECK_MINUTES`).

## Інтерфейс

Уся взаємодія йде через інлайн-кнопки під одним повідомленням-панеллю: натискання змінює це
повідомлення на місці, а тексти, які користувач вводить (IP-адреса, опис), бот видаляє. Сповіщення
про світло теж стають новою панеллю, стара видаляється, тож у чаті завжди одне-два повідомлення.
Команди: `/start`, `/menu`, `/version`, `/restart` (розширений режим), `/admin` (лише адмін).

## Запуск

```
python -m venv .venv
.venv\Scripts\pip install -r requirements.txt
copy .env.example .env     # і заповнити
.venv\Scripts\python bot\bot.py
```

## Налаштування `.env`

| Змінна | Призначення |
| --- | --- |
| `BOT_TOKEN` | токен від @BotFather (обов'язково) |
| `TUYA_ACCESS_ID`, `TUYA_ACCESS_SECRET` | ключі Cloud-проєкту Tuya (для стандартного режиму) |
| `TUYA_ENDPOINT` | дата-центр проєкту, за замовчуванням `https://openapi.tuyaeu.com` |
| `TUYA_LOCATION` | адреса в стандартному режимі, за замовчуванням «Богдана Хмельницького 67а» |
| `TUYA_DEVICE_ID` | стежити лише за цими пристроями (через кому); без нього — за всіма пристроями акаунта |
| `TUYA_PUSH` | `1` вмикає push-канал Tuya (експериментально), за замовчуванням вимкнено |
| `TUYA_PUSH_VERIFY_SECONDS` | пауза між перевірками стану в API після push, за замовчуванням 15 |
| `TUYA_PUSH_CHECKS` | скільки перевірок підряд мають підтвердити зміну, за замовчуванням 1 |
| `TUYA_POLL_SECONDS` | як часто питати Tuya про стан, за замовчуванням 120 |
| `TUYA_PUSH_LOG_RAW` | `0` вимикає запис сирого JSON push-повідомлень у лог, за замовчуванням увімкнено |
| `IP_CHECK_MINUTES` | період пінгу IP-адрес у розширеному режимі, за замовчуванням 10 |

Без `TUYA_ACCESS_ID` / `TUYA_ACCESS_SECRET` бот працює, але лише в розширеному режимі.

## Як підключити пристрій Tuya

1. Пристрій додано в застосунок Smart Life, він онлайн. Вмикати його треба у звичайну розетку, не в ДБЖ.
2. На [iot.tuya.com](https://iot.tuya.com) → Cloud → Development → Create Cloud Project
   (Industry: Smart Home, Development Method: Smart Home, Data Center: Central Europe для України).
   Залиште API-сервіси за замовчуванням (IoT Core, Authorization Token Management, Smart Home
   Basic Service) → Authorize.
3. У проєкті, вкладка Overview: скопіюйте **Access ID** і **Access Secret** у `.env`.
4. Вкладка Devices → Link App Account → Add App Account: відскануйте QR у Smart Life
   («Я» → значок сканера). Після цього пристрій з'явиться в списку Devices.
5. Cloud → Cloud Services: переконайтесь, що IoT Core активний (безкоштовний доступ періодично
   треба продовжувати кнопкою на сайті).

Tuya помічає розрив зв'язку із запізненням 1–3 хвилини, тож сповіщення приходить не миттєво.

Квота безкоштовного IoT Core — 26 тисяч запитів на місяць. Опитування раз на 2 хвилини —
це 21,6 тис. запитів на місяць (разом із токеном і перевірками змін ≈ 22,3 тис., у 31-денному
місяці ≈ 23 тис.), тобто близько 86% квоти. Раз на 3 хвилини ≈ 15 тис., раз на 5 хвилин ≈ 9,4 тис.
Показ статусу користувачам запитів не витрачає.
